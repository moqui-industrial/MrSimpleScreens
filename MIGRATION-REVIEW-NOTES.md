# MrSimpleScreens migration: items for the review pass

Kept by the coordinator while the screen batches run, from the subagents' reports. Each item names the group that found it. Host (MR-Moqui) changes made along the way are listed by file so the review of all mr-moqui changes has one place to start; the commits themselves are the full record.

## Decisions pending

- **Mantle view change (Asset, ast):** `mr-mantle-usl/entity/ProductAssetViewEntities.xml`, `ProductMaintenanceDetail`: `join-optional="true"` on the UOM, PMTR, PMUOM and MTENM joins. With inner joins the "Planned Maintenance" drop-down is empty unless a maintenance has both a UOM and a meter. This is in another repository; confirm it belongs there.
- **Request comment edit (MyAccount):** the Edit button on a nested reply always errors with "Comment N not found on request"; Mantle's `update#RequestComment` only accepts comments joined to the request. Service-contract question.
- **Java parity of `build_url` (Accounting setup, acs):** the Rust `build_url` adds the screen's declared parameters (here `partyId`) to transition URLs, which is how the "Add GL Account" options request got a `partyId` filter. Is that Java behavior? If not, the `parameter-map="{organizationPartyId:'', partyId:''}"` override in `OrgSettings/GlAccounts.xml` is unneeded but harmless.
- **Possible lost edit:** the acs agent ran `git checkout` on `crates/moqui-tui/src/link.rs` to undo its own first attempt (against the no-checkout rule); check that file's diff in the review in case another agent's uncommitted edit was dropped.
- **FinancialRatios total (Accounting Reports, acr):** Total Assets shows -225,404.94 while the Balance Sheet shows 225,283.74; the screen only displays what `run#FinancialRatios` returns. Check in Mantle.
- **`asOfDate` shifts a day (Accounting documents, acd):** `mantle.account.InvoiceServices.get#ReceivableStatementInfo` (mr-mantle-usl) formats its `Date` parameter in the user's time zone; with a US/Central user `asOfDate=2026-10-01` printed as 30 Sep and the aging buckets shifted. Decide how `Date` parameters should reach scripts.
- **`appRoot` is `simple` (acd):** `SimpleScreens.xml` hard-codes `simple` but the suggested mount in `MoquiConf.xml` is `SimpleScreens`; every `//${appRoot}/...` link, including party links, is disabled when mounted as `/apps/SimpleScreens`. Decide the mount name or make appRoot follow the mount.
- **`display text=""` after a link (acd):** FindPayment/EditPayment form-singles show the raw ID because empty text falls back to the field value (as Java's `?has_content`), and the TUI drops the link. Probably the same in Java.
- **mr-mantle-udm data change (Catalog, cat):** `runtime/component/mr-mantle-udm/data/MantleUdmSetupData.xml`, the `ProductAmountNameTemplate` localized message used `amountFixed!=1`, which throws "decimal valueOf is not supported" for any product with an amountFixed (breaks `getProductAmount` in Manufacturing FindRun/RunProduced and QuickLookup). Now `!toDecimal(amountFixed).eq(1)`. Separate git repo, uncommitted; confirm it belongs there.
- **Mantle/host bug, second picklist (Shipping, shp):** `ShipmentWorkServices.create#ShipmentLoadsForOrders` fails with "cannot read property 'statusId' of null" as soon as it must create a second picklist. `add#OrderPartToShipmentLoad` has `entity-find-one ... for-update="true"`, which returns null for a row inserted earlier in the same transaction; dropping `for-update` made it work. A direct service call reproduces it and `ShipmentLoads.spec` only covers one picklist. BulkPicklist is ticked since the screen is not the problem. Host entity or service fix needed.
- **TUI `go` URL parser (shp):** repeated parameters (`statusId=A&statusId=B`) keep only the last value; comma-joined values work, which is what the real client sends. This was the real cause of the earlier "multi-element array" suspicion for FindShipment/PackageTracking (the Set econdition works there).
- **`ec.web.sendJsonResponse(entityList)` sends "<object>" (Party, pty):** should the host convert entity lists to maps? Other screens work around it by mapping to plain objects (getPartyClassificationList/getPartySettingList, getOrgFiscalPeriods now do).
- **Empty string for a nullable foreign key in a list-row update (pty):** PartyRelated Update with a blank To Role gave a role_type foreign-key violation in the host's auto-update. Does Java Moqui null out empty strings there?
- **List-row `link` does not post its value (pty):** PartyRequests Update failed with "primary key requestId is required"; `<hidden/>` added. The upstream XML has the same flaw (HTML renderer probably posts the same way), same as AssetParties.
- **TaskSummary editables (Project/Task, prj):** Status and Resolution edit as typed text in the TUI because their choices come from `editable-load`, which the TUI does not fetch. Should the TUI fetch `editable-load` choices, or should TaskSummary offer a status drop-down?
- **`mantle.work.TaskServices.delete#TaskComment` (prj):** deleting a comment that has replies fails with a foreign-key error. Should the service handle replies? (Same shape as the nested-reply edit question from MyAccount.)
- **Wiki breadcrumb (Request/Wiki/Survey, rws):** the `json_envelope` change below drops the extra path of `allow-extra-path` screens from `pathList`, so the TUI breadcrumb loses the space name (`wiki ▸ RWS1 ▸ Wiki` becomes `Wiki`); the fix stops the client from asking for bogus parent levels `Wiki/wiki` and `Wiki/wiki/RWS1.tui`, which ran the wiki pre-actions and showed "Which page?" / "Space not found". Check whether a better fix keeps the breadcrumb.
- **`store#WikiPageCategoryMember` (rws):** stored the page's `versionName` parameter as an extra field in the member row when the add-category dialog is submitted from a versioned wiki URL. Survey `createFormResponse` has no UI anywhere (as the original); `create#DbFormFieldOption` accepts an empty option row (as the original).
- **MyAccount `User/Calendar/EventDetail.xml` (pmo):** same `<set field="statusId" from="invoice?.statusId"/>` and `WorkEffortAssetAssign#moqui.basic.StatusItem` pattern that blanked the status in Manufacturing EditRun (fixed there); not fixed in EventDetail.

## Hazards seen in the port

- Groovy-to-JS date and decimal semantics that the batches keep finding: `timestamp - timestamp` is milliseconds in JS (AssetStatusByReceipt days), period dates are UTC midnight so local formatting shows the day before, raw timestamps print as epoch millis, `charAt(0).letter` and decimal `+` need `toDecimal(...).add()`.

- `${x?.y}` on a null renders "undefined" in the JS port; the same may exist in other screens (grep for `?.` in label text and `${}` strings).
- Screens link through `//${appRoot}`; mounting SimpleScreens as `SimpleScreens` makes those links vanish in the TUI where the screens set `appRoot` to another name (Asset scratch mount used `simple`).
